# Module 37: MCP in n8n Self Hosted

## Overview

This module explains how to use MCP inside a self-hosted n8n environment. The lesson covers the difference between cloud-based MCP tools and local MCP/stdio support, how to install the MCP community node, and how to configure a local MCP client tool that can connect to a server using stdio or HTTP/streamable.

---

## What is MCP?

MCP (Model Connector Protocol) is a tool abstraction layer that allows a client or agent to connect to an MCP server and discover or invoke tools dynamically, without manually wiring every tool resource and operation.

Key MCP concepts:

- MCP server: exposes tools in a standard protocol.
- MCP client: connects to an MCP server and uses tools without hardcoding each tool.
- Tool discovery: the client lists available tools and decides which to run.
- Protocol types: HTTP, HTTP-streamable, SE, and stdio.

### Why MCP matters

- MCP avoids the need to define every tool resource and operation manually.
- It enables a more dynamic, agent-style workflow where the model chooses tools via the server.
- It is especially useful for self-hosted local automation where tool invocation should be centralized.

---

## Cloud vs Self Hosted n8n MCP behavior

### n8n Cloud MCP

- n8n cloud supports MCP server connectors like HTTP-streamable and SE.
- This is good for connecting remote MCP services, but it does not fully demonstrate the value of stdio-based local MCP.
- Cloud use often relies on manually adding tools instead of using MCP as a discovery layer.

### n8n Self Hosted MCP

- Self-hosted n8n supports the same MCP client options as cloud, including HTTP-streamable and SE.
- It also offers the possibility to use stdio-based MCP when the right community node is installed.
- Local self-hosted environments can therefore run MCP servers on the same machine and access tools without putting every tool on the internet.

### Important limitation

- `stdio` MCP is not well supported out of the box in the default n8n installation.
- The lesson explains that this is the main gap to solve for true local MCP use.

## Installing the MCP community node

Self-hosted n8n can install community nodes like plugins or extensions.

Steps from the demo:

1. Open n8n settings from your user profile menu.
2. Navigate to `Community nodes`.
3. Search for `MCP`.
4. Install the MCP community node package.
5. Accept the prompt that you understand the risk of installing third-party nodes.

### Why this is required

- The default n8n install does not include the advanced MCP client/node.
- The MCP community node adds support for new MCP credentials and tools.
- Once installed, the MCP client tool appears in the agent tool list.

---

## Creating an MCP agent and tool

After installing the community node, the workflow is:

1. Create an agent in n8n.
2. Add a chat model such as OpenAI chat for convenience.
3. Add a new tool and select the MCP client tool provided by the community node.
4. Configure the MCP tool credential.

### Important credential options

- The MCP client credential can support `SE`, `HTTP-streamable`, and `stdio`.
- The lesson favors `stdio` for local server attachments.
- For remote servers, `HTTP-streamable` or `SE` are also valid.

## Running stdio MCP on local n8n

The transcript provides a step-by-step summary for stdio MCP setup:

1. Open Settings > Community nodes.
2. Install the MCP community node.
3. Create an agent.
4. Add the updated MCP client tool from the installed community node.
5. Configure the stdio credential and the command line that will launch the MCP process.
6. Provide required environment values such as the API key.
7. Save the credential and run a chat query.

### Practical command setup

- The lesson references using `npm` or `npx` to install the MCP client package.
- It also notes the specific versioning issue: using `0.14` instead of `0.1.4` caused a failure.
- The correct approach is to install the latest MCP package or the exact supported version, typically via `npm i -g @mcp/cli` or equivalent.

### Handling credentials

- Add environment variables in the credential configuration.
- The example shows adding `API_KEY` or a Tab key to the stdio process environment.
- Proper environment injection is required so the child MCP process can authenticate.

## Troubleshooting MCP connection

The demo captures a real failure and its fix:

- Initial attempts failed with `Failed to connect to MCP`.
- The root cause was installing the wrong npm package version (`0.14` instead of `0.1.4` or the latest supported release).
- After correcting the package version, the MCP client connected successfully.

### Why version matters

- MCP community nodes can depend on specific MCP CLI versions.
- A wrong version may not support the credential type or protocol.
- Always use the version recommended by the community node or the latest stable release.

## MCP client behavior and tool execution

Once configured correctly, the MCP-enabled agent demonstrates these behaviors:

- The agent can list available tools from the MCP server.
- The MCP client can execute `list tools` and `execute tool` operations automatically.
- The model does not need explicit tool wiring; it can allow MCP to choose and run the tool.

### Example flow

1. Ask the agent: "Tell me news about AI.".
2. MCP client lists available tools on the MCP server.
3. MCP selects the correct search/news tool.
4. MCP executes the tool and returns the results.

This is the ideal MCP experience: the model delegates tool selection and execution to the MCP server.

## Key lessons from the demo

- Local n8n self-hosted can support MCP in the same way as cloud, but stdio support requires community extensions.
- MCP is designed for server-based tool discovery, not manual tool-by-tool wiring.
- Installing the MCP community node unlocks a richer local integration path.
- Use `stdio` for local MCP when possible; `HTTP-streamable` and `SE` are alternatives for remote servers.
- Fixing version mismatches is often the most important troubleshooting step.

- Install the MCP community node in your self-hosted n8n instance.

- Test with a simple query to verify tool discovery and execution.
