## Overview

This lesson shows how to add persistent chat memory and a Postgres-based vector store using Supabase (a hosted Postgres platform) inside an n8n RAG workflow. It covers credential setup, connection troubleshooting, session-based chat memory, and retrieving documents from Supabase-backed vector storage.

---

## Why use Supabase / Postgres for memory

- Supabase offers a managed Postgres DB with extensions useful for storing embeddings and session data.
- Postgres-based memory allows durable, queryable conversation history (per-session) and fine-grained metadata.
- You can store both chat history (session variables) and vector embeddings in the same managed DB.

---

## Connecting n8n to Supabase (Postgres)

1. In n8n, choose the `Postgres chat memory` option (or create a new Supabase/Postgres credential).
2. From your Supabase project, copy the connection details: `host`, `port`, `database`, `user` and `password`.
3. Paste these into the credential form in n8n and save.

Notes from the demo:
- Default Postgres port is `5432`, but some projects or connection strings may show other ports (e.g., `6543`). Confirm the value in Supabase.
- If `Cannot reach` or `Could not connect` appears, double-check host/IP, port, and password, and confirm the project is running and public access is allowed.

---

## Handling credential hiccups (demo highlights)

- The instructor initially had a password mismatch; re-check the Supabase project password and create a fresh project or rotate the DB password if needed.
- If connection fails repeatedly, recreate credentials and ensure you copy the `DB password` from the Supabase project settings.
- Supabase may show multiple connection variants (direct, pool, stateless). Use the appropriate connection details for your n8n environment.

## Creating and using session-based memory

- Once connected, create a new chat session in the workflow (the demo shows creating a session and sending "hi").
- Each session gets a `session_id`; n8n stores session history rows in Postgres tied to that `session_id`.
- You can view chat `history` and see `load memory variables` entries for the session — this mirrors how services like ChatGPT maintain multiple chat threads.
- Query examples from the demo:
  - Ask content-specific questions (e.g., "What is Attention about?") — the RAG retrieval will locate relevant chunks and answer.
  - Follow-up prompts like "Make it simpler in less than 100 words" reuse the same session context (memory) so the model can summarize.

---

## Supabase as vector store + retrieval

- The demo uses Supabase as both a memory store and a vector store (embedding storage + retrieval).
- You can add a `Supabase` node in n8n to read rows or query the vector store.
- Typical retrieval flow:
  1. User query → embed query with same embedding model used at ingestion.
  2. Search Supabase vector table for top-k nearest vectors.
  3. Retrieve chunk text and metadata and pass to LLM for grounded answer.

Practical tips:
- Keep embeddings and query embeddings created with the same model for alignment.
- Store metadata (source, offsets, document name) to enable provenance and filtering.
- Use Supabase row filters to narrow retrieval (e.g., by namespace, doc type, or date).

## Troubleshooting & Recommendations

- Confirm the correct `port` and `host` values from Supabase (default `5432`).
- If you get `Cannot reach 0.0.0.0` or similar, ensure you're using a reachable host (do not use an internal placeholder IP in credentials).
- If you forget the password, rotate/reset it in Supabase and update n8n credentials.
- Prefer a stateless connection (transaction pool) for serverless environments; choose the connection type that matches your deployment.
