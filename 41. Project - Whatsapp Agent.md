# Module 41: Project - WhatsApp Agent

## Overview

This module builds a WhatsApp-based AI automation project using self-hosted n8n and Meta Business APIs. The project demonstrates connecting WhatsApp messages to an n8n workflow, using an AI agent for conversational handling, and storing patient records and tickets in Airtable.

---

## Project goal

Create a WhatsApp agent that:

- receives incoming WhatsApp messages
- uses an AI agent to understand user intent
- stores and retrieves patient data via Airtable
- sends WhatsApp replies automatically
- supports an automation use case for doctor/patient communication

---

## Key components

- n8n self-hosted workflow engine
- WhatsApp trigger and send message nodes
- OpenAI chat model (`gpt-4.1-mini`) for AI responses
- AI Agent node for decision-making
- Airtable tools for patient records and ticket creation
- Simple memory buffer to maintain session context

---

## Requirements for WhatsApp integration

The project requires:

1. n8n self-hosted instance
2. WhatsApp account
3. Facebook account
4. Meta Business account
5. Meta Business App for WhatsApp
6. WhatsApp Business Cloud API credentials

### Why Meta matters

WhatsApp is part of Meta, so WhatsApp automation must be configured through Meta Business / Facebook Business settings. This includes creating a business portfolio, app, and API credentials.

## Self-hosting strategy

The demo chooses a self-hosted n8n deployment on Hostinger rather than relying on n8n cloud free trial.

Benefits:

- avoids trial limitations and workflow purges after 14 days
- supports 24/7 operation with no workflow execution caps
- is more suitable for agency and consulting use cases

Hostinger setup notes:

- choose a VPS plan with enough vCPUs
- use a coupon code for discounts
- prefer a plan that supports 100+ workflows if needed

## Meta Business setup

### Business portfolio

- Log in to `business.facebook.com` with your Facebook account.
- Create or select a Meta business portfolio.
- Ensure your account is connected to a business, not a consumer app.

### Create a Meta Business App

- Go to Apps in Business Settings.
- Create a new app and choose `Business` as the app type.
- Set the app use case to `Other` if needed.
- Provide a name such as `n8n-app-2`.
- Complete any password or verification steps.

### Important notes

- Use a business account app; otherwise WhatsApp connection may fail.
- If your Facebook account is old or locked, restore access before proceeding.
- Mobile number verification may be required.

## Configure WhatsApp API credentials

The WhatsApp setup requires two credential sets:

1. App credentials for the WhatsApp trigger
2. Business credentials for sending WhatsApp messages

### App credentials

- In your app settings, go to `Basic`.
- Copy the App ID and App Secret.
- Use these values when creating the WhatsApp trigger credential in n8n.

### WhatsApp Cloud API setup

- In the Meta dashboard, add WhatsApp Business Cloud and OnMessage features.
- Start the API setup flow and copy required values.
- Obtain the Business Account ID and access token for the WhatsApp send node.

---

## Creating a permanent access token

The project includes a permanent or long-lived token strategy.

Steps:

- In Meta Business Settings, go to `Users and System Users`.
- Create or select a system user such as `admin`.
- Assign assets to the app and WhatsApp product.
- Grant full control permissions for WhatsApp Business Messaging and Business Management.
- Generate a token and choose `Never` expiry if supported.
- Use this token for the WhatsApp Business Cloud send message nodes.

### Why permanent tokens matter

- avoids frequent reauthentication
- is better for consulting and production use cases
- prevents workflow breakage from token expiration

## Doctor query automation use case

The project is framed around a doctor-patient automation scenario:

- patients message the doctor on WhatsApp
- basic clinical or prescription questions are handled automatically
- urgent or ambiguous cases are flagged for human review
- patient details and medical history are stored in Airtable

### Benefits

- frees the doctor from routine questions
- provides faster patient support for non-emergency queries
- preserves context and history for follow-up conversations
- enables downstream automation with structured patient data

---

## n8n workflow design

### Nodes used

- `WhatsApp Trigger`: receives incoming messages.
- `AI Agent`: processes incoming text and chooses actions.
- `OpenAI Chat Model`: generates responses.
- `Airtable Tool` nodes: create tickets and patient records.
- `Memory Buffer`: stores session context keyed by phone number.
- `Send message`: returns the answer back to WhatsApp.

### Connectivity

- The WhatsApp trigger feeds the incoming text to the AI Agent.
- The AI Agent uses tools such as Airtable record lookup and ticket creation.
- The OpenAI chat model provides natural language responses.
- The final agent output is sent via the WhatsApp send node.

---

## Data and memory flow

The workflow stores patient data in Airtable, including:

- patient profile records
- previous diagnoses
- prescriptions and medical notes
- support tickets

Memory is maintained using a session-based buffer keyed on the WhatsApp phone number so the agent can remember recent context during the conversation.

## Testing and validation

Example test flow:

1. Execute the workflow in n8n.
2. Send a WhatsApp message such as `Hi`.
3. Confirm the trigger receives the message.
4. Validate the AI Agent response.
5. Check that Airtable records and tickets are created correctly.
6. Inspect execution logs for any invalid request errors.

### Common issues

- invalid Airtable table requests due to credential or schema mismatch
- missing WhatsApp credentials for trigger or send nodes
- incorrect token or business account ID

### Troubleshooting

- review workflow execution logs
- refresh credentials and reconnect the WhatsApp nodes
- verify Airtable tool configuration and field mappings
