## Overview

This module introduces the n8n Self Hosted AI Starter Kit, a curated open-source repository that boots a secure local AI workflow environment. It replaces the basic local n8n Docker run with a richer self-hosted kit that includes n8n, a vector database, Postgres, and Ollama.

---

## Why use the Self Hosting Kit?

- The basic local n8n Docker setup is quick but limited for production-style use.
- The self-hosting kit bundles a full AI workflow environment with:
  - n8n self-hosted instance
  - Ollama local LLM support
  - Quadrant vector store
  - Postgres database
- It is designed to support local AI, document indexing, memory, and external integrations more robustly.

---

## Getting the self-hosting kit

The demo recommends using the official n8n Self Hosted AI Starter Kit repository.

Typical setup steps:

1. Clone the repository from GitHub.
2. `cd self-hosted` or the kit directory.
3. Copy `.env.example` to `.env`.
4. Edit the `.env` file with your Postgres credentials, encryption keys, and other required values.

This scaffold is the foundation for a proper local AI stack.

---

## What the kit includes

The kit's Docker Compose setup typically includes:

- `n8n` with persisted data and saved workflows
- `postgres` as the primary database
- `quadrant` as the local vector store
- `ollama` for local model hosting
- `ngrok` for tunneling and public exposure

The demo specifically points out that Quadant is a PostgreSQL-backed vector store and that Postgres is the data engine behind the stack.

---

## Docker Compose configuration

Key ideas from the demo:

- The kit includes a prebuilt `docker-compose.yml` defining service volumes, networks, and environment variables.
- The kit often avoids exposing all internal ports by default, while still letting internal services communicate on a Docker network.
- If you want direct Postgres access, you can expose Postgres on a host port like `5435`.
- n8n runs on `5678`, Quadrant on `6333`, and Ollama commonly on `11034`.

---

## Local model support with Ollama

- The starter kit runs Ollama inside the container alongside n8n.
- The demo shows pulling and running `llama-3.2` in the local container.
- This enables fully local model inference without sending data to an external LLM provider.
- For Mac users, the kit recommends either CPU-only mode or running the model outside Docker if GPU access is limited.

---

## Mac-specific notes

- Apple Silicon users cannot expose native GPU into Docker like NVIDIA or AMD systems.
- For macOS, the recommended option is running Ollama in CPU mode or running model services externally and connecting from n8n.
- The `.env` file may require setting `OLLAMA_HOST` to `host.docker.internal:11034` for Docker-to-host connectivity.

---

## Adding ngrok into the stack

- The demo extends the kit by adding ngrok directly into Docker Compose.
- Running ngrok inside the container removes the need to start it from the host terminal.
- This enables internal services to create a public tunnel from within the containerized environment.
- The `.env` file should include the ngrok auth token and public domain URL.

---

## Advantages of the enhanced stack

- Persistent storage for workflows, credentials, and settings.
- Local vector DB and AI model support in one environment.
- External access via ngrok without exposing `localhost` directly.
- More production-like containerization compared to the default local Docker run.
- Easier to deploy to a server or cloud VM later, since the stack is already Docker Compose based.

---

## Practical tips from the demo

- Delete old containers before restarting if container names collide.
- Allow the stack time to download large images for Postgres, Quadrant, n8n, Ollama, and ngrok.
- Confirm the correct Docker Compose profile for your hardware (CPU, NVIDIA, AMD).
- Use the self-hosted kit to avoid the 14-day trial and save workflows locally.
- For local testing, keep the kit on a Docker network and only expose the necessary public endpoints.

- Run `docker compose up` and wait for all services to start.
- Verify n8n, Quadrant, and Ollama are reachable in the Docker network.
