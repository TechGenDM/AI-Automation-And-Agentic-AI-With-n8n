# 44. Project - Github AI Technical Assistant

## Overview

This module covers a GitHub technical documentation assistant built with n8n, Google Gemini, Pinecone, and a lightweight frontend.

The project demonstrates how to turn a code repository into a conversational AI assistant using Retrieval-Augmented Generation (RAG). It is designed for developers and non-technical users who need a searchable knowledge base for repositories, documentation, policies, onboarding material, and technical Q&A.

## What problem does it solve?

- Makes large or evolving documentation searchable
- Keeps sensitive data in a private RAG pipeline rather than exposing it to public chat services
- Allows users to ask natural questions about code and repository structure
- Provides a scalable way to serve answers for onboarding, documentation, and developer support

## Core Idea

1. Extract repository metadata and source files from GitHub.
2. Chunk and embed code/docs into a vector store (Pinecone).
3. Use a query webhook to search the vector store.
4. Send relevant chunks to a Gemini-powered AI agent.
5. Return a concise, context-aware answer through a frontend.

## High-Level Architecture

- Frontend: Lovable UI or any chat entry point (Telegram, Slack, WhatsApp, Gemini app)
- Backend: n8n workflows, including webhook receivers, AI agents, vector search, and GitHub integration
- Vector Store: Pinecone holds semantic embeddings of repository chunks
- LLM: Google Gemini handles chat, context composition, and answer generation
- Data Source: GitHub repo URL + branch information

## Manual Process vs Automation

### Manual process

- Read the repository content
- Build a mental map of folders and files
- Understand where information lives

### Automated process

- Send repository URL and branch to a webhook
- Extract repo owner, repo name, and branch from the URL
- Use GitHub API to list files and fetch content
- Chunk content, embed it, and store vectors in Pinecone
- Use a chat webhook to answer questions using the indexed repository data

## Key Components

### GitHub integration

- Input: GitHub repository URL and branch
- Use GitHub API to fetch the repository tree
- Filter files by extension and size
- Exclude generated artifacts like `node_modules/`, `.git/`, `dist/`, `build/`, `venv/`, and compiled files
- Fetch file contents for supported text files only

### Vectorization pipeline

- Convert code and documentation chunks into embeddings
- Store chunks in Pinecone with metadata: file path, repo, branch, and file type
- Keep the embedding model consistent across ingestion and query time

### n8n backend workflow

- Webhook node to receive repository indexing requests
- HTTP request / GitHub node to fetch file trees and file contents
- Code node to parse repo metadata and prepare a filtered file list
- Pinecone node to upsert embeddings into the vector store
- Webhook node to receive user query requests
- AI Agent node with Gemini chat model to process questions
- Simple Memory node to maintain short-term conversational context
- Respond to Webhook node to send answers back to the frontend

### RAG query flow

1. User asks a question via frontend
2. Query webhook receives the text
3. The system searches Pinecone for relevant chunks
4. Retrieved chunks are sent to Gemini with a prompt template
5. Gemini composes the final answer and returns it

## Prompt and agent behavior

- The AI is configured as a technical documentation assistant
- It should reference file paths and explain code structure
- The system prompt should instruct the agent to be concise, factual, and source-aware
- The prompt also defines how to handle large repositories and limitations

## Best practices from the project

- Keep the embedding model the same for indexing and retrieval
- Do not rely on ChatGPT for private repo knowledge; use your own RAG pipeline
- Use clear metadata so answers can cite file paths and repository context
- Make the webhook POST request include both repo URL and branch
- Build a reusable front-end entry point so the interface can be swapped later

## Practical implementation notes

- A lightweight UI was built with Lovable, but the front end can be any chat interface
- n8n self-hosted and cloud-hosted workflows behave similarly; self-hosted avoids trial expiration
- The repo indexer sends branch and repo info to GitHub, then processes the returned tree
- When a file is large, consider summarizing or chunking it before storing embeddings
- The answer workflow should use a structured response and may include follow-up clarifications

## Use cases

- Developer onboarding for large codebases
- Internal product documentation search
- Policy and HR document assistants
- Technical support bots for engineering teams
- Any scenario where answers must be sourced from a specific document repository

## Troubleshooting tips

- If the pipeline returns poor answers, verify that Pinecone returns the correct chunks
- Check the n8n execution logs for webhook requests and node errors
- Confirm the GitHub API token has permission to read the target repo
- Ensure the webhook payload includes branch and repo information
- If the same embedding model is not used, retrieval quality will degrade
