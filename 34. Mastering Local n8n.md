## Overview

This module covers running n8n locally in Docker, the common challenges of local self-hosting, and how tunneling with ngrok solves external webhook and integration access issues.

---

## Running n8n locally with Docker

The demo shows the easiest local setup using Docker Desktop:

- Pull the latest n8n image from Docker Hub.
- Run a container named e.g. `n8n-local`.
- Map port `5678` to your host.
- Optionally mount a volume for persistence and set environment variables.

Example Docker command:

```bash
docker run -it --name n8n-local -p 5678:5678 \
  -v ~/.n8n:/home/node/.n8n \
  n8nio/n8n:latest
```

After starting, open `http://localhost:5678` to access n8n.

---

## Local setup advantages

- Runs on any OS with Docker: macOS, Windows, Linux.
- Quick way to experiment with n8n workflows and integrations.
- Provides the familiar n8n UI and local development experience.

---

## Local setup pain points

The demo highlights several issues with the simple local Docker approach:

1. **Public access limitation**
   - Webhooks and external services cannot reach `localhost:5678` from outside your machine.
   - Telegram, WhatsApp, webhooks, and MCP servers fail because they need a public HTTP endpoint.

2. **Non-persistent workflow changes**
   - If n8n is started without proper volume persistence, workflows and settings are lost after restart.
   - The demo warns that default local runs often lose saved credentials and workflows.

3. **Local LLM connectivity issues**
   - Connecting to locally hosted models like Llama may fail if the container cannot reach the model host or if the service is not exposed correctly.
   - The instructor showed a local Llama instance running but n8n could not connect to it.

4. **Production-readiness concerns**
   - Basic local Docker runs are fine for experimentation but are not robust enough for enterprise or production deployments.
   - For production, you need a smarter container setup, persistent storage, and networking that supports external integrations.

---

## Key local hosting lessons

- `localhost` is safe for local development but not reachable by external systems.
- Every user has a different `localhost`, so external webhook or bot services cannot call your instance directly.
- Firewalls and network isolation further block direct access.
- A local container is still just a server, but you must expose it properly to the outside world.

## Solving public access with ngrok

The demo introduces ngrok as the tunneling solution for local n8n access.

### Why tunneling?

- External services need a public URL to reach your webhook.
- ngrok creates a secure public endpoint that forwards requests to your local port.
- This enables Telegram, webhooks, MCP servers, and other external integrations to reach n8n running on `localhost:5678`.

### ngrok setup steps

1. Install ngrok (via package manager or download from the ngrok site).
2. Authenticate with your ngrok API token.
3. Start an ngrok tunnel to port `5678`.
4. Use the public ngrok URL as the webhook URL or external callback endpoint.

Example command:

```bash
ngrok authtoken YOUR_NGROK_TOKEN
ngrok http 5678
```

---

## ngrok benefits

- Makes local n8n reachable externally.
- Useful for testing webhook-based integrations like Telegram and WhatsApp.
- Provides a temporary public URL without requiring server deployment.
- The demo also mentions the option of a free static domain in ngrok for a stable URL.

---

## When ngrok is needed

- Use ngrok when you want to test external triggers from services outside your network.
- Use it when your workflow needs to receive callbacks from cloud services.
- Use it for demoing locally hosted n8n without deploying to a public server.

---

## Recommended next steps

- Run n8n locally in Docker with a mounted volume for persistence.
- Set up ngrok and expose `localhost:5678` to the internet.
- Test a webhook trigger from Telegram or another external service.
- For more robust local hosting, consider using Docker Compose and adding dependent services (Postgres, Llama, vector store) into the same network.
