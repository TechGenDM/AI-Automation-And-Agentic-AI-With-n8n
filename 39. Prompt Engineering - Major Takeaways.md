# Module 39: Prompt Engineering — Major Takeaways

## Overview

This module distills the most important prompt engineering lessons into a compact set of practical principles. It focuses on what to include in a prompt, common prompt mistakes, and how to keep prompts clear, effective, and easy for models to execute.

---

## Core prompt components

A strong prompt should include:

1. Context
   - Who is the user or the role? Example: "You are an engineer," "You are a data analyst."
   - Provide only the relevant background needed for the task.
2. Instructions
   - Tell the model exactly what it must do.
   - Example: "Classify the feedback as positive, negative, or neutral."
3. Input data
   - Provide the content or examples that the model should use.
4. Output guidance
   - Specify how the answer should be returned.
   - Example: "Return the result as JSON with keys `sentiment` and `reason`."
5. Examples or format indicators
   - Give one strong example when needed to illustrate your desired output.

---

## The prompt engineering checklist

When writing a prompt, make sure you:

- Define the goal clearly.
- Specify the input and output formats.
- Create a role for the model.
- Clarify the audience.
- Provide the necessary context.
- Give examples or structure.
- Specify style and tone.
- Define the scope and restrictions.

---

## Practical prompt advice

- Define the goal first, then detail format.
- A role helps the model behave correctly.
- Clarify the audience so the response matches the target reader.
- Good context is essential; this is sometimes called context engineering.
- One clean example beats a long set of weak examples.
- Style and structure matter for predictable output.
- Restrict scope to avoid overly broad answers.

---

## Common prompting mistakes

### 1. Vague or ambiguous prompts

- Example: "Write a report." Without audience, length, or structure, the output can be inconsistent.

### 2. Biased prompts

- Avoid telling the model to favor one option or opinion without a valid reason.
- Example: "This research is always better." This introduces bias into the output.

### 3. Lack of context

- Asking for research without providing links, documents, or source material means the model has nothing concrete to work with.

### 4. Insufficient examples

- If your prompt needs to teach a pattern, provide a strong example.
- A weak or missing example makes it harder for the model to infer the correct structure.

### 5. Confusing or conflicting instructions

- Don’t combine contradictory directions like "keep it simple" and "write an in-depth technical analysis" for the same audience.
- Mixed audience signals lead to poor output.

### 6. Not testing prompts thoroughly

- Prompt engineering requires iteration and validation.
- If you don’t test prompts, you can’t know which version works best.

---

## Major takeaways

- Keep prompts simple but complete.
- Start with goal, then provide format details.
- Always assign a role.
- Explicitly clarify the audience.
- Provide context and examples.
- Specify style and scope.
- Apply restrictions where needed.
- Avoid vague, biased, or conflicting instructions.
- Test prompts with real examples and iterate.
