## Overview

This module demonstrates an end-to-end RAG (Retrieval Augmented Generation) workflow inside n8n using a vector store. It covers available vector DB options, the RAG starter template, the ingestion pipeline (upload → chunk → embed → store), and the retrieval/query flow via a chat interface.

---

## Vector Store Options

Common vector databases showcased:

- Pinecone — hosted vector DB with good performance and integration.
- Supabase — Postgres-based option with vector extensions.
- Quadrant — another vector DB alternative.

Note: n8n connectors and templates can be adapted to any vector DB with an API or SDK.

## RAG Starter Template (n8n)

- The course provides an n8n RAG starter template (a JSON workflow). Open the JSON to inspect nodes and flows.
- The template typically includes: a data loader, an embedding tool (OpenAI), and the vector-store insertion node.
- The demo uses OpenAI embeddings (example: `text-embedding-3-small`) for chunk embedding.

## Demo Walkthrough

1. Load data flow
   - Execute the "Load data" workflow which opens a form to upload a document (e.g., a PDF).
   - The workflow uses a data loader node (default in the template) which reads the document and extracts text.

2. Chunking and embedding
   - The extracted text is automatically chunked into multiple segments (the demo shows these chunks and metadata).
   - Each chunk is passed to the embedding model to produce vectors.

3. Store in vector DB
   - Embeddings and metadata are inserted into the vector database via the configured vector-store node.
   - The demo displays chunk creation, chunk count, and saved metadata entries.

4. Query via chat
   - Open the chat flow in the template and ask a question such as: "Who are the authors of the paper 'Attention Is All You Need'?"
   - The chat uses a `query data` tool node which embeds the query, searches the vector DB for top-k similar chunks, and returns the retrieved context.
   - The LLM (demo uses GPT-4-mini) generates a grounded response using the retrieved context.

## Important Implementation Notes

- Two-step RAG flow: ingestion (pipeline to load and index data) and retrieval (agent/chat to query the index).
- Keep ingestion separate: You can run the ingestion pipeline once to populate a reusable vector DB and then reuse the DB across multiple workflows.
- Embedding model consistency: Use the same embedding model for ingestion and query embedding — mismatch breaks similarity alignment.
- Overlap & chunk size: The template handles chunking automatically; verifying chunk sizes and overlap helps maintain answer context.
- Metadata: Store source, offsets, and other metadata with each chunk for traceability and provenance.

## Troubleshooting & Tips

- If retrieval returns poor results, ensure:
  - The embedding model is the same for ingestion and queries.
  - Chunking preserves meaningful sentence boundaries or uses overlap.
  - The vector DB is correctly indexed and searchable.
- For performance, consider precomputing embeddings offline and batching inserts into the vector DB.
- Use metadata filters in vector DB queries to narrow down relevant sources (date, document type, or section).
