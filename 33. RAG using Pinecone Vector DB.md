## Overview

This lesson demonstrates using Pinecone as the vector database for an n8n RAG workflow. It covers account setup, index creation, selecting embedding models and dimensions, generating API keys, and creating Pinecone credentials inside n8n.

---

## Why Pinecone

- Pinecone is a managed vector DB optimized for similarity search and scaling.
- Offers easy APIs, indexing options, and region choices (serverless/AWS regions).
- Good integration path with n8n via API keys and dedicated vector-store nodes.

---

## Quick Pinecone Setup (from demo)

1. Create a Pinecone account and sign in.
2. Create a new index (e.g., `document-db-123`).
3. When creating the index, select the correct embedding model dimension — many OpenAI embeddings use 1536 dimensions; adjust if your embedding model uses a different size.
4. Choose namespace/region (serverless/AWS region like `us-west1`, `us-east-1`, etc.) depending on latency and pricing needs.
5. Generate an API key for your project (create a new key named e.g., `rag`), copy it securely.

Notes from the demo:
- Select the same embedding model in Pinecone/n8n that you used to generate embeddings (model consistency is critical).
- If you get a dimension mismatch error, recreate the index with the correct dimension for your embedding model.
- Pinecone has a free tier for small experiments — check the console when creating the index.

---

## Create Pinecone credential in n8n

1. In n8n, open the Pinecone node or the RAG starter template's vector-store node.
2. Create a new credential and paste the Pinecone API key you generated.
3. Save the credential and test the connection.

Demo notes:
- The instructor created a credential, pasted the key, saved it, and the connection succeeded immediately.
- After credential creation, you can select the Pinecone index and namespace inside the node configuration.

---

## Index & Embedding Model Alignment

- Always use the same embedding model for ingestion and query embeddings.
- Common embedding dimensions:
  - OpenAI `text-embedding-3-small/large` — check returned dimension (commonly 1536 for some models).
- If you see an error about dimension mismatch when inserting vectors, recreate the index with the correct dimension.

---

## Typical Flow with Pinecone

1. Ingest documents in n8n: extract text → chunk → embed with chosen model.
2. Insert embeddings into Pinecone index (store chunk text + metadata).
3. At query time: embed the query → search Pinecone top-k → retrieve chunks → pass context to LLM.

---

## Practical Tips & Troubleshooting

- Check embedding dimension during index creation; many issues arise from dimension mismatches.
- Name indexes and namespaces clearly (e.g., `product-docs-us`, `papers-2024`) to avoid confusion.
- Keep API keys secure; rotate keys if exposed.
- For testing, create a small index and use the free tier before moving to production.
- If browser or login issues occur, try alternate sign-in methods (demo used Google sign-in and then adjusted settings).
